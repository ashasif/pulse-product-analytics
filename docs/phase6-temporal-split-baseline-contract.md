# Phase 6 — Temporal Split, Baseline and Preprocessing Contract

## Evaluation principle

Phase 6 uses chronological out-of-time evaluation. Random train/test splitting
is prohibited.

The split is based on the trial-start cohort date.

## Frozen partitions

### Training

January 2024 through June 2025.

The training partition is the only population allowed to fit:

- categorical encodings
- missing-value imputers
- scaling parameters
- prevalence estimates
- model coefficients or other model parameters

### Validation

July 2025 through December 2025.

Validation is used for:

- baseline comparison
- model selection
- model/hyperparameter comparison
- calibration decisions
- decision-threshold and targeting analysis before final lock

### Final test

January 2026 through May 2026.

The final test population is defined at Step 3 but must not be evaluated during
Step 3 or ordinary model-development iterations.

It is reserved for the final locked model evaluation.

### June 2026 boundary population

June 2026 is excluded from primary train/validation/test modelling.

Although the strict supervised maturity filter removes right-censored records,
this cohort remains closest to the production observation boundary and is
retained as a separate boundary/sensitivity population.

## Current expected production counts

- training: 4,173
- validation: 2,238
- final test: 1,991
- excluded June 2026 boundary cohort: 201

Total: 8,603.

## Baseline 1 — prevalence only

Fit one constant probability from the training conversion prevalence.

No validation or test outcomes may contribute to the constant.

This establishes the minimum probability-forecast baseline.

## Baseline 2 — static logistic regression

The second baseline uses only information that does not depend on Day-5 trial
behaviour:

- platform
- acquisition channel
- country
- billing period
- installation-to-signup time
- signup-to-trial time
- onboarding-start status by prediction time
- onboarding-completion status by prediction time

This measures how much predictive value exists before using explicit trial
engagement features.

## Preprocessing contract

Categorical predictors:

- one-hot encoded
- unseen categories ignored rather than causing scoring failure

Numeric predictors:

- median imputation fitted on training data only
- missingness indicators generated by the training-fitted imputer
- standardized using training-fitted scaling parameters

No preprocessing object may be fit using validation or test rows.

## Evaluation

Primary probability metric:

- Brier score

Secondary metrics:

- log loss
- ROC-AUC
- average precision / PR-AUC summary

The final test partition is not scored in Step 3.

## Step boundary

Step 3 establishes:

- frozen temporal partitions
- prevalence baseline
- static logistic baseline
- training-only preprocessing

Behavioural model development belongs to Phase 6 Step 4.
